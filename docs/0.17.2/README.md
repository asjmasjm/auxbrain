# AuxBrain 0.17.2：提问贡献与知识确认

## 提问贡献里的英文是什么

旧版把知识条目正文直接放进贡献按钮，有些条目保存的就是英文论文原文，因此出现大段英文。它不是新的回答，也不是推理过程。

现在只展示提问、时间、发生的变更和对应栏目，例如“新增 · 实验设置 · 2 项”。同一栏目、同类变更会合并，同一条目不会在该组重复计数。不同类型的变更可能关联同一个条目，不能把各组数量相加当作新增知识总数。点击栏目可查看知识和原文，原始内容没有被删除。

## 如何入库

1. 论文卡片 → 结构化知识 → 找到“待整理的原文”，点击“写下我的理解”。
2. 写出一句明确的理解，例如“本文用数据集 A 训练模型，用数据集 B 评测泛化能力”。必要时展开“知识分类（可选）”修改栏目或类型。
3. 点击“保存为待确认知识”。此时已经保存到本地数据库，但状态仍是待确认，并未自动纳入已确认知识。
4. 点击“确认入库”，核对结论与原文是否一致，再点击“确认并入库”。看到“已确认入库”才表示人工确认完成。

已有知识结论可直接从“核对结论”进入确认或修改。只在输入框里打字、没有点击保存，不会写入数据库。修改会保留原文和历史记录；若提交结果不确定，应先“重新读取状态”，不要重复提交。

这条流程保存的是带来源的文字知识条目，不等于自动产生实体关系或知识图谱连线。个人推断应使用“推断”类型，不应标为论文明确陈述。

## 原来的空 `{}` 是什么

它是内部的空“适用条件”对象，含义是没有额外记录模型、数据集、实验设置等条件，不是需要填写的特殊指令。

新版移除了 JSON 编辑框。没有条件时不显示空对象；已有条件使用可读的名称和值展示，并在保存理解时原样保留。主要操作只需要填写“我的理解”。已有结构化条件在此表单中为只读，不会因简化界面被清空。

## 更新

本次只改前端，当前兼容的后端即可执行保存与确认。关闭再开启 Obsidian 第三方插件中的 AuxBrain；只关侧栏不会重载。

完整功能仍建议 Companion 0.12.2。上版跨分段原文定位修复需要该运行包，不能仅更新前端生效。本版没有重启服务或修改个人数据，也不新增付费 LLM 调用。
